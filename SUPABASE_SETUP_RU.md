# CYBERDROP — облачные аккаунты и инвентарь

## Что это даёт

CYBERDROP использует Supabase Auth для регистрации/входа и Postgres для хранения профиля, кредитов, инвентаря и сборки ПК. Данные привязаны к Auth user ID, поэтому один аккаунт может использоваться на iPhone и компьютере.

## 1. Создайте проект Supabase

Создайте новый проект на supabase.com.

Вам нужны:
- Project URL
- Publishable key (или старый anon public key, если Dashboard показывает его как публичный ключ)

Никогда не вставляйте `service_role`/secret key в сайт.

## 2. Создайте таблицы и RLS

Откройте SQL Editor в Supabase и выполните:

`supabase/schema.sql`

Схема включает RLS-политики, которые разрешают пользователю видеть и менять только собственные строки.

## 3. Включите Email/Password

Supabase Dashboard → Authentication → Providers → Email.

Для первоначального теста можно отключить обязательное подтверждение email. Для реального публичного сайта лучше оставить подтверждение включённым.

## 4. Вставьте настройки

Откройте `supabase-config.js` и замените:

`YOUR_PROJECT_REF`

и

`YOUR_SUPABASE_PUBLISHABLE_KEY`

реальными значениями проекта.

## 5. Публикация

Загрузите содержимое папки на HTTPS-хостинг. Например, GitHub Pages, Netlify или Cloudflare Pages.

После публикации:
1. откройте сайт в Safari на iPhone;
2. зарегистрируйте аккаунт;
3. войдите тем же аккаунтом на ПК;
4. предметы и состояние должны загрузиться из облака.

## Важно про безопасность игровой экономики

Текущая интеграция делает авторизацию и состояние аккаунта облачными, но основные игровые операции всё ещё вычисляются фронтендом. Пользователь может технически изменить данные, которые клиент отправляет в базу.

Для публичного проекта следующий этап — перенести открытие кейсов, выдачу предметов, списание кредитов, награды мини-игр и пассивный доход в server-side RPC/Edge Functions. Тогда браузер больше не сможет сам назначать себе предметы и кредиты.

## Конфигурация CYBERDROP
Проект уже настроен в `supabase-config.js` с указанными Project URL и Publishable key.
Секретный/service_role ключ в браузерный код не добавляется.
